# chairlift-chat｜一起把一副滑雪眼镜做得没那么烦

这里是一张公开的产品讨论桌。

有人把雪场里遇到的麻烦写下来，大家补充、反驳、投票；维护者把结论和理由写回去。想法不需要包装成 PRD，也不用先证明自己是“专家”。滑过雪，或者被设备坑过，就有发言资格。

## 进来先做一件事

- **遇到过具体麻烦**：发一条[真实经历](https://github.com/Zionlzx/chairlift-chat/issues/new?template=story.yml)，先说发生了什么。
- **已经想好要怎么改**：发一条[功能建议](https://github.com/Zionlzx/chairlift-chat/issues/new?template=feature-request.yml)。
- **想把一个还没成形的念头聊明白**：去 [Discussions](https://github.com/Zionlzx/chairlift-chat/discussions)。
- **想知道哪些事有进展**：看 [公开路线图](ROADMAP.md)。

只想补一句也可以。比如：“零下十度戴着厚手套，按不到开始录制，等反应过来已经错过了。”这比一句“增加语音控制”更有用。

## 这里到底怎么运转

每个话题都会经历这几步：

```text
真实场景 → 大家补充和质疑 → 维护者给出结论 → 公开记录进度
```

我们用几个简单状态标记进展：

- **新鲜想法**（`idea`）：刚提出来，还在收集场景。
- **聊着呢**（`discussing`）：有分歧，先把取舍说清楚。
- **准备做**（`planned`）：进入近期计划。
- **做出来了**（`shipped`）：已经可以试用。
- **先放着**（`declined`）：暂时不做，同时写明原因。

这些状态会显示成 issue 标签，打开 [Issues](https://github.com/Zionlzx/chairlift-chat/issues) 就能按状态筛选。

点赞只是信号，不是许愿成功。一个真实场景、一个反例，往往比十个赞更能改变决定。维护者负责收束和安排，但每次采纳、暂缓或放弃都会留下理由。

## 我们希望这里像什么

- 说人话，少用“赋能、闭环、抓手”这类词。
- 反对一个想法没关系，最好带上自己的场景或代价。
- 身份可以自报，但身份不替观点加分。工程师会判断可不可做，滑雪新手也可以指出它好不好用。
- 不承诺还没确定的福利，不用“官方认证”给意见排座次。

具体边界见 [行为准则](CODE_OF_CONDUCT.md)。

## 为什么放在 GitHub

因为这里适合把讨论摊在桌面上：谁提了什么、大家担心什么、最后为什么做或不做，都能回头查。你可以 Watch 仓库，也可以只在想说话时回来，不需要加入任何会员体系。
